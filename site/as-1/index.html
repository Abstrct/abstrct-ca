AS-1: The Abstrct Standard

Status of This Memo

This memo defines a person. Distribution of this memo is unlimited, which is generous, since nobody asked for it.

1. Terminology

The key words MUST, MUST NOT, SHOULD and MAY are to be interpreted as described in RFC 2119. The key word GAME is to be interpreted as broadly as possible, and then a bit more.

2. Definitions

Subject: Josh McDougall, also known as Abstrct. No vowel was harmed in the making of this handle. It simply wasn’t invited.

Medium: any system that was not designed to contain a game.

3. Requirements

3.1. The Subject MUST put a game inside a Medium. Conformance has been demonstrated against:

  • a PostgreSQL databaseSchemaverse (DEF CON 19, 2011)
  • a cryptocurrencyCoindroids (DEF CON 22–28)
  • an entire blockchainStructs
  • a Super NintendoToronto Games

3.2. Once a game exists, the Subject SHOULD make it again in a different hat. Structs is currently also available as a toy box (pippop), a sky full of dragons (wyrmhodl), a Dreamcast game (structs.xyz) and some fur beasts (Furrency). A Super Nintendo hat is in progress.

3.3. The Subject MAY build a useful tool very quickly while a conference is already under way. See Tokens.fyi and the Key Ceremony Guide.

3.4. The Subject MUST NOT be asked to stop. Implementations that ask anyway are non-conformant.

4. Security Considerations

The Subject co-founded C4 and helped write the CryptoCurrency Security Standard, which is a real standard. This one is not.

Schemaverse was built so people could try to break into it. They did. That was the point.

5. Interoperability

The Subject also DJs. Sets are available over SoundCloud. No conformance testing has been carried out on the dance floor.
